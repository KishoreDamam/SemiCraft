# Round-Robin Arbiter — Test Plan

An 2-way round-robin arbiter: it grants a shared resource to at most one requester per cycle (one-hot grant, asserted the same cycle as the request), rotating priority so that under sustained contention every requester is served at least once every 2 cycles.

_Generated by SemiCraft 0.3.0 — config hash `ab00db50bcb5`. Derived from `rr_arbiter`'s `ExplanationDoc`, `port_groups()`, and `tb_spec()`; the Test Plan table mirrors exactly what `rr_arbiter_tb.sv` drives and checks._

## Features Under Test

Configuration exercised by this test plan:

- Requesters: 2 (req/grant are 2 bits, pointer is 1 bits)
- Grant style: combinational (grant asserts the same cycle, no latency, longer critical path from req through the priority network)
- Arbitration policy: rotate — priority advances past the granted requester every grant (pure round-robin)
- Reset: sync, active-low
- Output language: Verilog-2001

**Reset behavior:** The active-low (asserted when 0) reset clears the priority pointer to 0 synchronously on the rising clock edge while reset is asserted, so after reset requester 0 holds highest priority and no grant is asserted.

## Not Covered / Limitations

- Unweighted round-robin: every requester has equal priority in the rotation; there is no way to bias or prioritise a requester.
- No grant/acknowledge protocol: grant is asserted per the fixed latency of the chosen grant_style; the arbiter does not wait for an ack before rotating.
- N (2) is fixed at generation time: the priority network is unrolled for this exact requester count and is not a runtime parameter.
- Combinational grant places the full two-pass priority network on the req-to-grant critical path; at large N consider the registered style for timing closure.
- Directed, not randomized: the smoke TB only runs the fixed vectors in `TbSpec.vectors`; no constrained-random or exhaustive stimulus is attempted.
- Default parameterization only: the generated TB instantiates the DUT with no parameter overrides, so only the exact configuration used to generate this file is exercised. A different parameterization of the same RTL is not covered by this TB.
- Single clock/reset domain only: this TB drives one free-running clock and (if present) one reset; it performs no clock-domain-crossing verification.
- No `Check` samples cycle 0 (the first cycle after reset release): reset behavior runs structurally but is not directly self-checked by this TB.
