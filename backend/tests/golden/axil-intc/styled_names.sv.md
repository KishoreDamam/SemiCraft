### Interrupts

Request lines in, one masked request out. Inputs are synchronised before they are latched.

| Port | Direction | Description |
| --- | --- | --- |
| `p_irqIn` | input | Asynchronous interrupt requests; a rising edge on a synchronised line sets that source's PENDING bit. |
| `p_irqOut` | output | High while any enabled source is pending; the OR of STATUS. |

## Register map

`INTC` — 32-bit data, 4-bit byte address (16 B decoded, 12 B used), 4-byte stride. Offsets are relative to the IP's base address.

| Offset | Name | Reset | Description |
| --- | --- | --- | --- |
| `0x00` | `PENDING` | `0x00000000` | Latched interrupt requests; write 1 to clear. |
| `0x04` | `ENABLE` | `0x00000000` | Per-source mask; 1 lets the source reach irq_out. |
| `0x08` | `STATUS` | `0x00000000` | PENDING & ENABLE — the sources actually requesting. |

Reset values are as *software* reads them, so a write-only (WO) field contributes zero.

### `PENDING` — offset `0x00`

Latched interrupt requests; write 1 to clear.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[7:0]` | `value` | W1C | `0x00` | Latched interrupt requests; write 1 to clear. |

## Configuration

- Sources: 8
- Trigger: edge
- Input synchroniser: 2 stages
- Registers: 3 (16 B decoded, 12 B used)
- Reset: sync, active-low (fixed by AXI4-Lite)
- Output language: SystemVerilog

## Assumptions

- irq_in is asynchronous to aclk and is synchronised before use; a request takes 3 clocks to appear in PENDING.
- Sources are active-high.

## Limitations

- Flat priority: irq_out says that something is pending, not what. Software reads STATUS to find the source.
- No vectoring, no nesting, and no per-source priority.
- PENDING has one bit per source, so a second request arriving before the first is cleared is not counted.
- Edge-triggered: a source already high when the controller leaves reset produces one request, then nothing until it deasserts and rises again.
