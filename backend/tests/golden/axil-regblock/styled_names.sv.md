# AXI4-Lite Register Block

An AXI4-Lite target that serves a register map: address decode, byte-strobe writes, per-access-type field behaviour, and a registered read path. The register-map metadata it is built from is the same model the datasheet is rendered from, so the two cannot drift.

## Register map

`REGS` — 32-bit data, 5-bit byte address (32 B decoded, 20 B used), 4-byte stride. Offsets are relative to the IP's base address.

| Offset | Name | Reset | Description |
| --- | --- | --- | --- |
| `0x00` | `CTRL0` | `0x00000001` | Control register 0. |
| `0x04` | `STATUS0` | `0x00000000` | Status register 0. |
| `0x08` | `IRQ0` | `0x00000000` | Interrupt flags 0. |
| `0x0C` | `CMD0` | `0x00000000` | Command register 0. |
| `0x10` | `SCRATCH` | `0x00000000` | Full-width scratch register; reads back what was written. |

Reset values are as *software* reads them, so a write-only (WO) field contributes zero.

### `CTRL0` — offset `0x00`

Control register 0.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[7:4]` | `level` | RW | `0x0` | Four-bit level output (bit 3 is reserved). |
| `[2:1]` | `mode` | RW | `0x0` | Two-bit mode output. |
| `[0]` | `enable` | RW | `0x1` | Enable output; set out of reset. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `STATUS0` — offset `0x04`

Status register 0.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[7:4]` | `code` | RO | `0x0` | Hardware status code. |
| `[0]` | `busy` | RO | `0x0` | Hardware busy indication. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `IRQ0` — offset `0x08`

Interrupt flags 0.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[3:0]` | `flags` | W1C | `0x0` | Interrupt flags; hardware sets, software writes 1 to clear. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `CMD0` — offset `0x0C`

Command register 0.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[3:1]` | `code` | WO | `0x0` | Command code; reads back as zero. |
| `[0]` | `go` | WO | `0x0` | Command strobe; reads back as zero. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `SCRATCH` — offset `0x10`

Full-width scratch register; reads back what was written.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[31:0]` | `value` | RW | `0x00000000` | Scratch value. |

## Configuration

- Data width: 32 bits (4-byte address stride)
- Address width: 5 bits (32 B decoded, 20 B used)
- Registers: 5 (control 1, status 1, irq 1, command 1, scratch)
- Field layout: named sub-fields
- Reset: sync, active-low (fixed by AXI4-Lite)
- Output language: SystemVerilog

## Assumptions

- One AXI clock domain; the hardware face is synchronous to it.
- A single outstanding transaction per channel — a new write is accepted only once the previous response has been taken.
- awready/wready are functions of registers only, never of awvalid/wvalid, so there is no combinational valid-to-ready path.

## Limitations

- No awprot/arprot: the block enforces no protection policy, so declaring inputs it never reads would be dead logic (and would fail the project's -Wall lint gate). An interconnect that drives them simply leaves them unconnected.
- The full byte address is decoded, so an access whose low offset bits are non-zero returns SLVERR rather than aliasing onto the containing word.
- Writing a 1 into a reserved bit returns SLVERR and performs no update — stricter than a block that silently ignores such bits.
- The reset is named areset and renders areset_n; the spec spells it ARESETn. The naming engine owns the active-low suffix, and integration matches on bundle roles rather than spelling.
- One transaction at a time: no write/read overlap, no pipelining.
