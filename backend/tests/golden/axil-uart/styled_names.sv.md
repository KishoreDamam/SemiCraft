## Register map

`UART` — 32-bit data, 4-bit byte address (16 B decoded, 16 B used), 4-byte stride. Offsets are relative to the IP's base address.

| Offset | Name | Reset | Description |
| --- | --- | --- | --- |
| `0x00` | `STATUS` | `0x00000000` | Transmitter and receiver status. |
| `0x04` | `TXDATA` | `0x00000000` | Writing this register starts a transmission. |
| `0x08` | `RXDATA` | `0x00000000` | The most recently received byte. |
| `0x0C` | `BAUDDIV` | `0x00000004` | Clocks per bit. |

Reset values are as *software* reads them, so a write-only (WO) field contributes zero.

### `STATUS` — offset `0x00`

Transmitter and receiver status.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[3]` | `frame_error` | W1C | `0x0` | The stop bit was not high. |
| `[2]` | `rx_overrun` | W1C | `0x0` | A byte arrived while one was still waiting. |
| `[1]` | `rx_valid` | W1C | `0x0` | A byte is waiting in RXDATA; write 1 to clear. |
| `[0]` | `tx_busy` | RO | `0x0` | The transmitter is shifting a byte out. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `TXDATA` — offset `0x04`

Writing this register starts a transmission.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[7:0]` | `data` | WO | `0x00` | Byte to transmit; reads back as zero. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `RXDATA` — offset `0x08`

The most recently received byte.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[7:0]` | `data` | RO | `0x00` | Received byte; valid while STATUS.rx_valid is set. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `BAUDDIV` — offset `0x0C`

Clocks per bit.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[15:0]` | `div` | RW | `0x0004` | Baud divisor; at least 2. |

## Configuration

- Reset baud divisor: 4 clocks per bit (BAUDDIV is writable at run time)
- Input synchroniser: 2 stages
- Framing: 8N1 (fixed)
- Registers: 4 (16 B decoded, 16 B used)
- Reset: sync, active-low (fixed by AXI4-Lite)
- Output language: SystemVerilog

## Assumptions

- uart_rx is asynchronous and is synchronised before sampling.
- BAUDDIV is at least 2: the receiver waits half a divisor to reach mid-bit, and half of one is zero.
- Software writes TXDATA only while STATUS.tx_busy is clear; a write during a transmission is ignored rather than queued.
- Both ends agree on the line rate; there is no auto-baud.

## Limitations

- 8N1 only: no parity, no 5/6/7-bit words, no two-stop-bit mode.
- No FIFOs — one byte deep each way. A second byte arriving before software reads RXDATA sets STATUS.rx_overrun and the older byte is lost.
- Status flags are write-1-to-clear rather than read-to-clear: the register block has no read-side effect, and adding one for a single user was not worth a new access type.
- No hardware flow control (RTS/CTS) and no break detection.
- A framing error sets STATUS.frame_error but the byte is still delivered; the receiver does not resynchronise mid-frame.
