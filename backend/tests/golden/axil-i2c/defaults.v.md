# AXI4-Lite I2C Master

An open-drain AXI4-Lite I2C master. Software runs the bus one primitive at a time through CMD — optionally a START, then one byte written or read, then optionally a STOP — which is how a real transaction is assembled. The AXI frontend is the register-block generator spliced into this module.

### I2C bus

Open-drain bus (bundle `i2c`). A pad is `line = oe ? 1'b0 : 1'bz`.

| Port | Direction | Description |
| --- | --- | --- |
| `scl_in` | input | Level sensed on SCL; low while a slave stretches the clock. |
| `sda_in` | input | Level sensed on SDA. |
| `scl_oe` | output | Pull SCL low. The line is never driven high. |
| `sda_oe` | output | Pull SDA low. The line is never driven high. |

## Register map

`I2C` — 32-bit data, 5-bit byte address (32 B decoded, 20 B used), 4-byte stride. Offsets are relative to the IP's base address.

| Offset | Name | Reset | Description |
| --- | --- | --- | --- |
| `0x00` | `STATUS` | `0x00000000` | Transfer status. |
| `0x04` | `CMD` | `0x00000000` | Writing this register runs one bus command. |
| `0x08` | `TXDATA` | `0x00000000` | Byte to write, MSB first. |
| `0x0C` | `RXDATA` | `0x00000000` | Byte read from the bus. |
| `0x10` | `CLKDIV` | `0x00000002` | Quarter bit period in aclk cycles. |

Reset values are as *software* reads them, so a write-only (WO) field contributes zero.

### `STATUS` — offset `0x00`

Transfer status.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[3]` | `rx_valid` | W1C | `0x0` | RXDATA holds a byte read from the bus. |
| `[2]` | `ack_err` | W1C | `0x0` | The slave did not acknowledge a written byte. |
| `[1]` | `done` | W1C | `0x0` | The last command finished; write 1 to clear. |
| `[0]` | `busy` | RO | `0x0` | A command is in progress. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

### `CMD` — offset `0x04`

Writing this register runs one bus command.

| Bits | Field | Access | Reset | Description |
| --- | --- | --- | --- | --- |
| `[4]` | `stop` | WO | `0x0` | Emit a STOP condition afterwards. |
| `[3]` | `ack` | WO | `0x0` | On a read: 1 acknowledges, 0 sends NACK (last byte). |
| `[2]` | `read` | WO | `0x0` | Shift a byte in and send the ACK bit below. |
| `[1]` | `write` | WO | `0x0` | Shift TXDATA out and read the slave's ACK. |
| `[0]` | `start` | WO | `0x0` | Emit a START condition first. |

Bits not listed above are reserved and read as zero. What a write to them does is the register block's policy — see the IP's own documentation.

## Configuration

- Quarter-period divisor: 2 aclk cycles (an SCL period is four times this; CLKDIV is writable at run time)
- Input synchroniser: 2 stages on both lines
- Registers: 5 (32 B decoded, 20 B used)
- Reset: sync, active-low (fixed by AXI4-Lite)
- Output language: Verilog-2001

## Assumptions

- A pad turns each enable into an open-drain driver: `line = oe ? 1'b0 : 1'bz`, with an external pull-up.
- Both bus lines are asynchronous to aclk — other devices drive them — so each is synchronised before the FSM looks at it.
- Software assembles transactions from CMD primitives and observes STATUS.ack_err after each written byte.
- CLKDIV is at least 1; a quarter period of zero has no meaning.

## Limitations

- Single master: no bus arbitration and no lost-arbitration detection, so this must be the only master on the bus.
- No repeated START as a distinct primitive — issue a STOP and a fresh START, which works with most devices but is not identical on the wire.
- No 10-bit addressing and no general-call handling; the address is just the first byte software writes.
- No SMBus timeout, no PEC, no clock-low timeout — a slave that stretches forever stalls the master forever.
- No slave mode.
